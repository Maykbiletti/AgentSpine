# Honcho self-hosting admission

AgentSpine may act as the scope and policy gateway for a self-hosted Honcho deployment, but it does not treat an inference endpoint as a Honcho server and it does not run two writable memory systems at once.

`evaluateHonchoAdmission(plan)` is a side-effect-free, fail-closed pre-deployment gate. It does not contact a server, install Honcho, write memory, or prove that a declaration is true. A production cutover still needs receipts from the actual BLUN host.

## Required boundaries

- `honcho.serverUrl` is the root URL of a separately deployed Honcho API, never the managed Honcho service and never an LLM or embedding URL.
- Server, embedding, and derivation roles use distinct host/port sockets; changing only the URL scheme or mixing `localhost` with a numeric loopback alias cannot bypass that separation. Exactly three origins are pinned in server, embedding, derivation order, and the plan must mirror that sequence exactly; set equality is insufficient. Embedding model and dimension count and the derivation model are pinned separately. The plan cannot approve a new private endpoint, swap endpoint roles, or select another model for itself.
- Every endpoint host must also be a numeric private-network address, loopback, or `localhost`. RFC 1918, Tailscale CGNAT (`100.64.0.0/10`), and IPv6 ULA addresses are eligible. An allowlist entry alone cannot turn a public address or DNS name into a BLUN-internal endpoint.
- Evaluation keeps AgentSpine as the only writer and Honcho read/write disabled. Cutover reverses that ownership and leaves AgentSpine as `scope-gateway`.
- Every request binds tenant, workspace, user, project, and thread identifiers. Only confirmed private sources are eligible.
- Telemetry is disabled and raw credentials are forbidden recursively in the admission plan, including singular or plural credential containers, provider-prefixed API/access-key fields, common state-qualified copies such as backup, previous, legacy, primary, secondary, current, old, copy, or value, Unicode compatibility or single-code-point confusable forms of credential names, token/secret aliases, auth and authentication headers, passwords/passphrases, cookies, and private-key fields. Known token quota and usage fields are accepted only as nonnegative safe integers; ambiguous token fields and string or structured values remain forbidden. The plan must be a bounded JSON-compatible plain-data graph: functions, proxies, accessors, symbol keys or values, `undefined`, `BigInt`, non-finite numbers, negative zero, non-enumerable object properties, sparse arrays or arrays with named properties, custom prototypes, cyclic or overdeep structures, more than 4,096 properties, property names over 256 UTF-8 bytes, individual string values over 8 KiB, and more than 128 KiB of aggregate string-value bytes fail closed before policy fields are read, executable traps can run, or serialization can alter or unboundedly expand the checked value. Shared acyclic objects remain valid. Blockers use fixed redacted plan locations because untrusted property names can themselves contain secret material. A later transport may refer to a separately managed credential environment variable, but must not persist its value.
- Background derivation is asynchronous, tool-less, parent-history-free, fail-open, and has no automatic retries.
- A production cutover requires a distinct SHA-256-bound receipt for each of live server health, embedding compatibility, derivation isolation, cross-session recall, deletion, and AGPL source availability. Every receipt also carries a field-domain-separated binding over its digest, canonical UTC observation time, and the exact tenant, workspace, user, project, and thread scope. Receipts older than 24 hours or more than five minutes in the future are rejected. Boolean claims, cross-gate replay, unchanged cross-scope replay, and stale same-scope replay are insufficient.
- Every production receipt is signed separately with Ed25519 over its binding digest. A bounded, monotonically versioned BLUN trust store is supplied to the evaluator from local deployment configuration, outside the untrusted admission plan; its complete options graph and every direct trust-store, production-options, or evidence-binding input—including revoked proxies and non-string digest or timestamp scalars—must pass non-executable type and bounded-data preflight before field access, array inspection, pattern matching, or serialization. The plan carries only the selected key's SHA-256 SPKI fingerprint, exact trust revision, and canonical trust-store digest. Every key or revocation change increments that revision. The revision and digest are included in each signed evidence binding. Separate protected deployment state pins both the minimum revision and expected store digest, rejecting an older store or a different key/revocation set relabelled with the same revision even when its signatures remain cryptographically valid. The store may overlap old and new public keys during rotation, while its revocation digests always win even when the revoked public key remains present. A substituted or revoked key, rolled-back, altered, or malformed trust store, revision or digest mismatch, missing signature, or signature copied between evidence fields fails closed. Only public keys belong in this evaluator input; private signing keys never belong in AgentSpine state, the trust store, or the plan.

## BLUN endpoint status

The supplied King endpoint at `http://100.74.238.1:8000/v1` is an OpenAI-compatible inference endpoint, not a Honcho API endpoint. Reusing its origin as `honcho.serverUrl` is rejected even though the upstream Honcho development server also commonly listens on port 8000.

The supplied Ollama endpoint at `http://100.74.238.1:11434/api/embed` is a native Ollama embedding endpoint. Current upstream Honcho documentation configures Ollama embeddings through the OpenAI-compatible transport and a `/v1` base URL. AgentSpine therefore records the native endpoint as not yet directly compatible; it must not silently rewrite the URL or claim production readiness. A separately verified compatible endpoint or explicit adapter is required.

The gate contains no endpoint probe. Reachability, model identity, vector dimensions, quota/accounting behavior, and data isolation must be verified from the authorized 65er host without logging private source bytes.

DNS names are rejected by the static gate because their resolved addresses can change after admission. Supporting an internal DNS name requires a later, separately reviewed host-attestation design that binds the name and resolved private addresses without weakening this fail-closed boundary.
